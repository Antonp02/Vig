# VIG v1.0 — Scope Notes

Target: data collection through 2026, public launch 2027.

Primary objective: **make Fantasy Lab mirror the real league format**, and make
the draft tab reflect roster construction rather than a flat pick count.

---

## 1. Roster format (CONFIRMED from ESPN roster screen)

**Ten starters, six bench, sixteen roster spots.**

| # | Slot | Eligible positions |
|---|------|--------------------|
| 1 | QB   | QB |
| 2 | RB   | RB |
| 3 | RB   | RB |
| 4 | WR   | WR |
| 5 | WR   | WR |
| 6 | TE   | TE |
| 7 | FLEX | RB, WR, TE |
| 8 | OP   | QB, RB, WR, TE |
| 9 | D/ST | team defense |
| 10 | K   | K |
| 11-16 | BE x6 | any |

12 teams x 16 spots = **192 total picks, 16 rounds.**

The earlier "possible K slot" ambiguity is resolved: the ESPN roster view shows
K as the tenth starter, then an EDIT BENCH section with six BE rows.

Consequences:
- Draft board is 12 x 16 = 192 cells, not 12 x 5.
- Two positions (D/ST, K) need scoring built from scratch — see §2 and §2b.
- The OP slot remains the superflex driver. See §3.

### Slot assignment rule

When a player is drafted, fill in this order: **dedicated slot → FLEX → OP →
bench.**

A naive greedy fill is safe *here specifically* because the eligibility sets are
nested: `FLEX ⊂ OP`, and OP additionally covers QB. Filling the narrowest
eligible slot first can therefore never strand a later pick.

That guarantee breaks the moment a non-nested slot is added — e.g. a WR/TE-only
flex alongside the RB/WR/TE flex. If that ever happens, replace the greedy fill
with proper bipartite matching recomputed across the whole roster on every pick.
Note this in code so nobody "optimises" it later without understanding why.

## 2. D/ST — needs a second data pipeline

**This is the blocker.** The current 115 KB dataset cannot fill slot 9.

`stats_player_week_2025.csv` contains no team-defense rows. Verified positions
present: C, CB, DB, DE, DL, DT, FB, FS, G, ILB, K, LB, LS, MLB, NT, OL, OLB,
OT, P, QB, RB, S, SAF, TE, WR — individual defenders, never a unit. There is no
`DEF` or `DST` position.

D/ST fantasy points must be assembled from two additional nflverse releases,
both confirmed reachable:

```
stats_team/stats_team_week_2025.csv     570 team-week rows, 133 cols
schedules/games.csv                     272 completed 2025 REG games
```

**What team stats provides:** `def_sacks`, `def_interceptions`, `def_tds`,
`def_safeties`, `def_fumbles_forced`, plus tackles and QB hits.

**What it does not provide:** `points_allowed` — which is the single largest
component of D/ST scoring in most formats. Derive it from `games.csv` by
joining on season + week + team and taking the *opponent's* final score.
Sample row confirms the shape: week 1, DAL 20 at PHI 24 — so PHI's defense
allowed 20, DAL's allowed 24.

Also fold in the standard points-allowed tier table (0, 1–6, 7–13, 14–20,
21–27, 28–34, 35+) since that mapping is league-specific.

**Consequence for the pipeline:** `build-fantasy-data.mjs` grows from one fetch
to three, and emits a `defenses` array alongside `players`. Roughly 32 entries
with weekly point arrays — negligible size impact.

**Consequence for comparison:** D/ST can be compared to D/ST on points per
game, floor, ceiling, and consistency, but not on target share. The metric list
needs to be position-aware rather than fixed at seven rows.

### D/ST scoring — CONFIRMED (ESPN defaults)

```js
const DST_SCORING = {
  sack: 1, interception: 2, fumbleRecovery: 2,
  touchdown: 6, safety: 2, blockedKick: 2,
  pointsAllowed: [            // [maxPointsAllowed, points]
    [0, 5], [6, 4], [13, 3], [17, 1], [27, 0], [34, -1], [45, -3], [Infinity, -5]
  ]
};
```

Column mapping, all verified present in `stats_team_week_2025.csv`:

| Category | Source column | Perspective |
|---|---|---|
| Sack | `def_sacks` | own row |
| Interception | `def_interceptions` | own row |
| Fumble recovery | `fumble_recovery_opp` | own row |
| Defensive TD | `def_tds` | own row |
| Safety | `def_safeties` | own row |
| Blocked kick | `fg_blocked` + `pat_blocked` + `pt_blocked` | **opponent's row** |
| Points allowed | final score | **opponent's row** (`games.csv`) |

**Two of the seven categories come from the opponent's row, not the team's own.**
A team-stats row records kicks *that team* had blocked, so crediting a defense
with a block means reading the opposing team's row for the same game — the same
join direction as points allowed. Getting this backwards produces plausible-
looking but wrong numbers, which is the worst kind of bug.

Caveat: those column semantics are inferred from names, not documentation.
Spot-check one known game (a defense with a famous blocked kick) against a box
score before trusting the pipeline.

## 2b. Kicker — computable, but not pre-scored

Kickers **are** present in `stats_player_week_2025.csv` (543 rows, 42 distinct
kickers), but `fantasy_points` is zero for all of them — nflverse does not
pre-score kicking. It must be computed.

Everything needed is in the file:

```
fg_made_0_19  fg_made_20_29  fg_made_30_39  fg_made_40_49
fg_made_50_59 fg_made_60_    pat_made       fg_missed (+ distance buckets)
```

ESPN default scoring (FG 0-39 = 3, 40-49 = 4, 50+ = 5, PAT = 1), applied to
2025 REG:

```
 1 Ka'imi Fairbairn  HOU 12.9      7 Cameron Dicker    LAC 10.0
 2 Jason Myers       SEA 11.9     10 Cam Little        JAX  9.6
 4 Brandon Aubrey    DAL 11.0     12 Chase McLaughlin  TB   9.2  <- replacement
```

40 qualifying kickers at 4+ games. **K1 is only +3.8 ppg over K12.** Compare to
+14.9 for the top RB. A value-based board will naturally sort kickers into the
final round without any special-casing — which is the correct behaviour and a
good sanity check that the VBD maths is right.

### K scoring — CONFIRMED (ESPN defaults)

```js
const K_SCORING = {
  fg: [[39, 3], [49, 4], [Infinity, 5]],   // [maxDistance, points]
  pat: 1,
  missedFg: 0                              // see note
};
```

One honest flag on `missedFg`. I proposed 0 and that is what was agreed, but I
am not fully certain whether ESPN's true default is 0 or -1 — sources differ and
some league presets do penalise misses. It is a single config value and the
`fg_missed_0_19` through `fg_missed_60_` buckets are all available, so either
setting is a one-line change. Worth a glance at the league's scoring page to
confirm; not worth blocking on.

## 3. Superflex changes the draft pool, not just the roster

With an OP slot, up to two QBs start per team. In a 12-team league that is up
to 24 rostered QBs against 12 in a 1QB format — demand roughly doubles, and
elite QBs move into round 1.

The current draft pool is a hardcoded list with QBs at ranks 14, 18 and 25.
Running a superflex mock against that ordering will teach the wrong lesson
every time, which is worse than not having the feature.

**Fix: compute value-based rankings from the real data rather than hardcoding.**

Worked example against the real format, computed from `fantasy-2025.json`
(12 teams, 24 swing slots allocated FLEX = RB 8 / WR 12 / TE 4 and
OP = QB 8 / RB 2 / WR 2 — the allocation is an assumption and should be stated
in the UI, per the no-black-box rule):

```
replacement  QB20 = 15.8 ppg    RB34 = 9.6     WR38 = 11.3    TE16 = 10.3

  1 Christian McCaffrey RB  24.5  +14.9        9 Trey McBride     TE 18.6  +8.3
  2 Bijan Robinson      RB  21.8  +12.2       10 James Cook       RB 17.8  +8.2
  3 Puka Nacua          WR  23.4  +12.1       11 Amon-Ra St.Brown WR 19.1  +7.8
  4 Jahmyr Gibbs        RB  21.6  +12.0       12 Rashee Rice      WR 18.8  +7.5
  5 Jonathan Taylor     RB  21.3  +11.7       13 Chase Brown      RB 16.6  +7.0
  6 De'Von Achane       RB  20.2  +10.6       14 Josh Allen       QB 22.8  +6.9
  7 Jaxon Smith-Njigba  WR  21.2   +9.9       15 Derrick Henry    RB 16.4  +6.8
  8 Ja'Marr Chase       WR  19.6   +8.3       16 Cam Skattebo     RB 16.0  +6.3
```

Note where Josh Allen lands: 14th, despite the highest points per game of any
QB at 22.8. Even with the OP slot, QB replacement level is high enough that
raw scoring overstates positional value. This is exactly the correction the
static rank list cannot make.

All the inputs already exist in `fantasy-2025.json`:

1. Set replacement level per position from *this* roster format — with 12 teams
   and nine starters, replacement QB is roughly QB24 given the OP slot, versus
   QB12 in a 1QB league.
2. Player value = points per game − replacement points per game at that
   position.
3. Order the pool by that value.

This is the correct ordering for the actual format, it is derived rather than
asserted, and it is a genuine analytical feature — no free mock draft tool
adapts its rankings to a custom superflex roster.

CPU picks should draft from this ordering with a small random reach factor so
no two mocks are identical.

## 4. Player search

A search bar over the full pool. Requirements:

- Substring match on a normalised key. Add `sn` (search name) to the derive
  script: lowercase, strip punctuation and spaces — the same approach Sleeper
  uses with `search_full_name`, which correctly handles Ja'Marr, Amon-Ra and
  D.J. Do not write a bespoke normaliser at runtime.
- Filter by position and by "available" during an active draft.
- Show position, team, points per game in the selected scoring, and positional
  rank inline so the result is useful without a second click.
- Feeds three consumers: the comparison pickers (replacing the current
  `<select>` elements, which do not scale past a few hundred entries), the
  draft pool, and eventually the bet slip for fantasy props.
- Must include defenses once §2 lands.

Note the current dataset is 503 players at 4+ games. Searching the *entire*
player universe means either dropping the games filter or joining
`players/players.csv`, which adds inactive and rookie players who have no
weekly stats to compare.

## 5. Draft tab rehaul

Driven by §1 and §3:

- Board renders **roster slots**, not just pick numbers. Each team's column
  shows which of the nine slots are filled and which remain.
- User's roster panel shows the nine named slots in order, with the assigned
  player in each and the bench below.
- Positional need indicator — highlight slots still empty, and grey out picks
  that can only go to the bench.
- Position scarcity readout: how many startable RBs remain versus how many
  teams still need one. This is the market-psychology angle applied to a draft,
  and it is the same instinct as Line Winder.
- Draft pool ordered by value-based ranking (§3), not a static list.
- Keep the existing snake logic. `type` can also be linear or auction in
  Sleeper; auction is out of scope for v1.0 and should be filtered out rather
  than silently mishandled.

## 5b. League platform — it is ESPN, not Sleeper

Screenshots confirm the real league runs on **ESPN Fantasy** (ROSTER / MATCHUP /
PLAYERS / LEAGUE tabs, ESPN standings glossary, Disney+ house ad). This
materially changes the integration plan, and mostly in a good way.

**Confirmed league facts:**

| Setting | Value |
|---|---|
| Teams | 12 |
| Divisions | 2 — "Neptune" and "Atlantic", 6 each |
| Regular season | 14 games (records all sum to 14) |
| Starters | 9 confirmed, possible 10th (K) |
| Champion | decided by bracket, not record |

That last row matters if the mock ever mirrors standings. In 2024 the title went
to a 9-5 team while three separate teams finished 10-4. In 2025 a 9-5 team won
while a 7-7 team took third. Seeding is divisional and the playoff is a bracket,
so best record ≠ champion. Do not model the season as "highest points wins."

**Recommendation: do not build an ESPN integration for v1.0.**

ESPN has no official public fantasy API. The community-used endpoints are
undocumented, and private leagues require pulling `espn_s2` and `SWID` cookies
out of a logged-in browser session — an unacceptable onboarding step for
friends, and a fragile dependency besides.

Since the stated requirement is "mimic my league for now," the right answer is
to **hardcode this format as configuration** rather than fetch it:

```js
const LEAGUE_FORMAT = {
  teams: 12,
  divisions: ['Neptune', 'Atlantic'],
  regularSeasonWeeks: 14,
  slots: ['QB','RB','RB','WR','WR','TE','FLEX','OP','DST'],  // + K?
  bench: 6,
  scoring: 'ppr'
};
```

Zero auth, zero fragility, and it generalises later — swap the constant for a
fetched object and everything downstream keeps working. This is a simplification
of v1.0, not an expansion.

Sleeper stays in the notes below because it remains the only platform with a
clean public API. If the league ever migrates, or if other users arrive on
Sleeper, that path is ready. It is no longer a v1.0 dependency.

## 6. Sleeper league connection (deferred — no longer v1.0 critical path)

- Username → `user_id` → leagues → league object.
- Read `scoring_settings` from the **league** object, never
  `metadata.scoring_type` from the draft. The label says "ppr" but the real
  scoring lives per-stat, which is where TE premium and bonuses hide. Computing
  from the label would quietly invalidate the entire comparison feature.
- Read `roster_positions` to auto-detect the format rather than hardcoding §1.
  That is how this generalises past one league.
- Draft history via `/user/{id}/drafts/nfl/{season}` → `/draft/{id}/picks` for
  league-specific ADP. Show sample size next to it; at eight drafts the 95%
  range on an average pick position is roughly ±3 picks, so report round-level
  tendencies rather than a decimal.
- Player ID join must handle both numeric IDs and bare team abbreviations —
  Sleeper represents defenses as `"PHI"`, not a numeric ID.
- Trending adds/drops for a market-heat signal.

## 7. Notes on the 2027 timeline

Two things follow from launching in 2027 rather than this season.

**The dataset is a placeholder.** `fantasy-2025.json` should become 2026 data,
then 2027. The derive script already takes a season argument, so this is a
one-line change. Consider keeping multiple seasons and comparing
year-over-year — that becomes a feature nobody else offers casually.

**Data accumulation is the actual 2026 objective.** Odds snapshots and draft
history only accrue while something is running in production. Every week not
deployed is a week of Line Winder history that does not exist and cannot be
backfilled without paying for historical odds. By 2027 that archive is either
two seasons deep or empty, and that difference is not recoverable later.

The features can wait. The clock on the data cannot.
